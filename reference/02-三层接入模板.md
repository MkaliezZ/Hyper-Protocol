# 超维协议三层结构接入模板

先选一个实际任务，再填写以下六类对象。可以保存在同一文档中，也可以转成 JSON、YAML 或项目表单。正文中的方括号为待填写项；未取得的事实和评议如实标记。模板本身不提供运行器或机器校验器。

## 1 场景说明

| 字段 | 填写内容 |
| --- | --- |
| 场景身份 | [项目与场景编号] |
| 服务对象与受影响者 | [谁使用、谁受结果影响] |
| 问题与目标 | [本次希望发生的具体变化] |

| 规则组合 | [通用协议版本、领域包版本、项目配置版本] |

## 2 判断规则包

规则包应让另一个执行者理解目标和标准，并知道何时不适用。每个主题指定唯一维护源；其他入口引用该来源。

```yaml
policy_id: "[命名空间.主题]"
policy_version: "[版本]"
protocol_version: "0.1-draft"
status: draft
maintainer: "[维护者]"
authority_source: "[谁以何种方式确立本规则]"
scope:
  subjects: ["[适用对象]"]
  tasks: ["[适用任务]"]
  conditions: ["[成立条件]"]
  exclusions: ["[排除或失效条件]"]
goals:
  - "[所追求的具体价值]"
priorities:
  - "[真实冲突发生时的取舍规则]"
rules:
  - rule_id: J01
    kind: hard_gate
    when: "[何时触发]"
    requirement: "[应满足的要求]"
    rationale: "[该要求保护的价值或专业依据]"
    evidence_required: ["[需要什么证据]"]
    evaluation_method: "[代码检查、模型评议、人工评议或组合]"
    positive_example: "[满足规则的例子及原因]"
    counterexample: "[容易误判的例子及原因]"
    missing_behavior: "[缺项时可以做什么、不能得出什么]"
quality_dimensions:
  - dimension_id: Q01
    name: "[质量维度]"
    anchors: "[可比较的具体表现；不评分时写评议依据]"
    minimum: "[最低项或不设数值阈值]"
preferences:
  - "[可被项目配置调整的表达或体验偏好]"
decision_authority:
  automated_scope: ["[已授予自动决定权限的事项]"]
  reserved_decisions: ["[由指定角色决定的事项]"]
conflict_behavior: "[规则冲突的处理方式]"
revision_record: "[修改内容、理由、案例、影响与维护记录]"
```

`hard_gate` 表示不能由其他高分抵消的要求；`quality_dimensions` 用于比较质量；`preferences` 用于可以调整的偏好。采用者可自行实现字段表示，但应保留三者区别。

## 7 三个判断规则示例

以下为本协议的设计示例，便于理解迁移方法；它们尚未作为新规则部署到历史产品。

### 7.1 伴学反馈

- **场景**：学生提交一份作答，希望得到下一次练习的建议。
- **判断规则**：反馈引用具体作答和任务标准，区分独立表现、已知帮助和未记录条件；提出可实施的改进动作。
- **正例**：指出论证中缺少支撑的句子，引用原答，安排针对该差距的新任务。
- **反例**：原题经提示答对后，直接判定学生已独立掌握该能力。
- **功能执行**：核验学生与任务范围，读取原答及帮助记录，生成并检查反馈，按已有权限保存或交教师确认。
- **资产留存**：任务、原答、帮助、反馈及其规则和版本引用。

### 7.2 校园空间的视觉改进

- **场景**：提高某地标在校园场景中的辨识度。
- **判断规则**：按实际用途评议体量、构造、空间关系、材料与表现形式；精度与不确定项应对应来源。
- **正例**：依据来源修改轮廓、庭院和入口关系，通过无纹理图检查几何，再查看最终页面。
- **反例**：仅更换颜色就宣称完成了真实建筑形体修复。
- **功能执行**：建模或修改场景，重建资源，检查路线与交互，提供可查看的前后结果。
- **资产留存**：参考来源及使用范围、旧模型、新模型、资源版本和检查图。

### 7.3 硬件读值解释

- **场景**：解释设备显示电量与原始电量读数之间的差别。
- **判断规则**：区分采样有效、表显换算、充电状态和实际容量；每类结论使用匹配证据。
- **正例**：保留原始读数，单列显示百分比与校准配置，说明本次验证的具体范围。
- **反例**：屏幕显示 100% 后，宣称电池实际容量已经完成测量和校准。
- **功能执行**：取得读值、核对有效性、按规则换算、保存配置并提供恢复方式。
- **资产留存**：固件版本、设备范围、诊断、校准参数及验证记录。
