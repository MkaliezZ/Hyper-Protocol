# 超维协议项目证据与蒸馏记录

本记录说明协议从哪些项目职责中提炼而来，并区分既有实践与本版新增设计。出处由协议编制时的项目文件提供；本包提供来源索引和提炼说明，原始项目文件不随包分发。项目原有验收结论不等同于本协议的重新验证。

## 1 任务与调用范围

- **任务类型**：已有项目反向抽象与协议内容产出。
- **当前阶段**：超维协议 v0.1 定义草案。
- **明确指令**：三层正式名称为判断层、功能层、资产层，沿用既有职责进行通用化。
- **主要依据**：伴学三层架构、科研三层职责、独立判断层，以及校园、课程、媒体、硬件、作品集、桌面工具和技术文档中的实际规则。
- **交付范围**：新协议定义、接入模板、证据记录与入口文档。
- **规则状态**：命名采用当前明确指令；新提出的通用义务、字段和发行方案保留 draft。

协议编制时读取相关项目的架构、规则或验收说明，以产品族覆盖的方式提炼共同职责。各目录下的全部项目和全部历史文件未逐一审计。超维项目、规划与链接按已读架构中的状态作为适配设计，不能由本稿推定已全部实现。

## 3 可以抽象为通用机制的内容

| 通用机制 | 主要依据 | 提炼理由 |
| --- | --- | --- |
| 判断、执行、保管三种责任分别说明 | E01、E02、E03 | 同一职责关系已跨伴学、科研与研究 Skill 出现 |
| 判断不限于形式，审美仍有具体对象 | E01、E03、E04、E10 | 专业依据、价值取舍和表达质量共同影响交付 |
| 实际结论绑定适用规则和材料版本 | E01、E02、E03、E07 | 版本变化会改变判断依据与可恢复性 |
| 不同领域选择不同证据和方法 | E02、E04、E06、E08、E12 | 实验、作品、视听、测量和文档各自有不同成立条件 |
| 工程、专业、审美、人工及现实使用分别记录 | E01、E02、E04、E06—E10 | 任一类通过都不能自动补足其他类证据 |
| 原件、衍生物、评价与公开成果可区分 | E01、E02、E07、E12 | 来源与加工性质影响可使用的结论 |
| 个案意见、通用规则和共享发布分别处理 | E01、E03、E07、E14 | 反馈的适用范围与公开用途并不相同 |
| 按已获权限继续工作，真正缺项才引入人工判断 | E03、E07、E09 | 有效协作需要减少重复询问，同时保留决定责任 |

## 4 保留在各自产品线的内容

- 伴学的具体题型、教学活动、量规与教师签名流程。
- 科研的特定实验设计、模拟模型、参数与工具选择。
- 校园的建筑轮廓、角色、地点、导航与身份接入方式。
- Studio 的课程阶段、质量门、受众和分发规格。
- 自媒体的镜头、字幕、声音、时间轴与具体平台指标。
- 学校项目研究的特定价值轴、权重、准入分级与示范样本。
- 固件的平台、引脚、分区、电量计门槛及按键时长。
- 作品集的折叠形式、作品数量和动效实现。
- 桌面时钟的网络计时与手动偏移设计。
- 中车材料的模板、经费、指标与行业结论。

这些内容可形成领域包或项目配置，应由对应任务选择。协议不把它们规定成其他产品的默认方法。

## 5 本次新增的协议设计

以下为综合提案，不能归为历史项目已经共同确认或部署的事实：

1. 用“通用核心＋领域规则包＋项目配置”表达规则的适用范围。
2. 给出 HD01—HD10 十条通用义务。
3. 统一六类交换对象及最小字段语义。
4. 提出接入检查、符合性声明和任务记录格式。
5. 提出公开仓库与规范、代码、案例的分别许可方案。
6. 将已定位产品族映射到统一定义，供后续逐项目接入。

## 6 转发版的范围与修订

转发包保留完整定义、全部接入模板、项目来源索引和新增设计说明，并补充快速使用、AI 接入提示词、示范任务与接入检查。

本包提供方法与示例。原始项目源码、用户数据、设备秘密、私有课程材料及商业底稿由各项目自行管理。

后续修订应记录改变的定义、字段、判断条件和接入要求，并注明受影响的领域包、实现及历史记录。
